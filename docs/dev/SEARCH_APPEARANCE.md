# Search Appearance: favicon & sitelinks

Two things Google shows next to a search result that are **not** read from the
page a visitor sees: the favicon and the sitelinks. Both are cached by Google
and refreshed on its own schedule, so after a brand change the site can be
correct for days or weeks while the result still shows the old icon or a stale
label. This doc records what was measured, so nobody re-debugs it as a site bug.

Last measured: **2026-11-24**.

---

## The favicon

### What Google requires

From <https://developers.google.com/search/docs/appearance/favicon-in-search>:

- **Supported formats: BMP, GIF, ICO, PNG, JPEG, PPM, TIFF — SVG is not
  supported.**
- "we recommend using a favicon that's larger than **48x48px**".
- It reads the `rel="icon"` link **on the home page only**; one favicon per
  hostname.
- "Allow time for Google to recrawl… can take anywhere from several days to
  several weeks." Indexing can be requested with the URL Inspection tool in
  Search Console.
- A favicon is never guaranteed.

### What was wrong

`app/favicon.ico` carried only 16 / 32 / 48 px, and the only other icon was
`app/icon.svg` — which is a format Google ignores. Next derives the head tag
from the largest ICO entry, so the home page advertised `sizes="48x48"`: the
single icon Google could read was at the very bottom of its recommended range.

### Current state

`scripts/build-favicon.mjs` generates both outputs from
`public/creedava-mark.svg`:

| Output | Contents |
|---|---|
| `app/favicon.ico` | 16 / 32 / 48 / 96 / 192 px PNG entries, 11.0 kB |
| `app/icon.svg` | same tile, vector, for browsers that prefer it |

Head output (measured on the live home page):

```html
<link rel="icon" href="/favicon.ico?favicon.…ico" sizes="192x192" type="image/x-icon"/>
<link rel="icon" href="/icon.svg?icon.…svg" sizes="any" type="image/svg+xml"/>
```

Both draw the C cream (`--mk-paper`, #F7F7F2) on a solid `--mk-brand` tile
(#005148), matching `app/apple-icon.tsx`. A transparent icon is composited onto
whatever background the browser uses; at 16 px the old transparent green C read
as an empty box.

`app/icon.svg` is kept because browsers like it — and because
`lib/utils/structured-data.ts` uses it as the JSON-LD `logo` — not because
Google does.

### Verifying it, without guessing

```bash
# what the site serves
curl -sO https://creedava.com/favicon.ico && file favicon.ico

# what Google has actually picked up (may lag the site)
curl -sL "https://www.google.com/s2/favicons?domain=creedava.com&sz=128" -o g.png
```

**Browsers cache favicons independently of Google and hard.** A normal reload
often keeps the old one. If the tab still looks wrong, open the site in a fresh
incognito window or a different browser before assuming the deploy failed. The
served bytes are the ground truth.

## Sitelinks

The indented links under a brand result are generated by Google. **There is no
API, tag, or markup that sets them**, and Search Console cannot edit them. They
refresh when Google recrawls and re-derives them.

A reported "About appears as ES" in the sitelinks could not be reproduced from
the site, and is not a page bug. Measured 2026-11-24:

- No `/es` route exists, and `/?lang=es` renders English.
- `pageAlternates()` declares only `en-US` and `x-default` — there is
  deliberately **no** `es` hreflang, because every page serves both locales
  from one URL (locale is a cookie) and an `es` entry would advertise a Spanish
  page that renders English to a crawler.
- The live home page contains **no anchor** whose text is `ES`; all 37 anchors
  were enumerated.
- The only `ES` token anywhere on the page is the language toggle's visible
  label, which appears twice in the header's rendered text (desktop + mobile).

Since Googlebot renders pages, a prominent standalone token like that is a
plausible source — but that is a hypothesis, not a measurement. Nothing in the
codebase forces a sitelink.

**Fastest lever:** Search Console → URL Inspection → request indexing for
`https://creedava.com/`. That is a manual step that needs the owner's login.

## Not covered here

- **Logo in Google Ads / Business Profile** is a separate, image-review surface
  with its own requirements; a Search favicon does not affect it.
- **`sitemap.xml` `lastModified` on the 11 static pages is the server start
  time** (i.e. the deploy), which is honest but means every deploy reports all
  static pages as changed. Google tolerates this; a per-page content date would
  be more precise if recrawl budgeting ever becomes a problem.
